Нужно реализовать отдельный сервис `gsm-sip-bridge-email`, который пересылает входящие SMS из `gsm-sip-bridge` по email.

Структура проектов:

* `~/gsm-sip-bridge` — основной проект `gsm-sip-bridge`.
* `~/gsm-sip-bridge/docker` — Docker Compose окружение основного проекта.
* `~/gsm-sip-bridge-email` — новый отдельный проект email-forwarder.

Требования:

1. Не изменять бизнес-логику и исходный код `gsm-sip-bridge`, если это не требуется для интеграции Docker Compose.

2. Forwarder должен работать отдельным Docker-контейнером и быть добавлен в Compose-конфигурацию в `~/gsm-sip-bridge/docker`.

3. Источник SMS — SQLite-база `gsm-sip-bridge`.

   * Сначала самостоятельно найти реальный путь к БД и изучить её текущую схему.
   * Не делать предположений о названиях таблиц и колонок.
   * База bridge должна монтироваться в контейнер forwarder только для чтения.
   * SQLite открывать в read-only режиме (`mode=ro`, `PRAGMA query_only=ON`).
   * Учитывать использование SQLite WAL и при необходимости монтировать весь каталог с `db`, `db-wal` и `db-shm`.

4. Forwarder не должен изменять никакие таблицы, поля или статусы в БД `gsm-sip-bridge`, включая существующую логику `forwarding_status`.

5. Собственное состояние хранить отдельно, например в `/data/state.db`.
   Нужно запоминать ID уже успешно отправленных SMS, чтобы после рестарта они не отправлялись повторно.

6. Логика:

   * периодически проверять появление новых входящих SMS;
   * извлекать номер отправителя, время и текст;
   * отправлять email;
   * только после успешной SMTP-доставки отмечать SMS как обработанную в собственной `state.db`;
   * при ошибке SMTP сообщение должно быть повторено позднее;
   * ошибка forwarder не должна влиять на работу `gsm-sip-bridge`.

7. Настройки SMTP задавать через environment variables / `.env`, например:

   * `SMTP_HOST`
   * `SMTP_PORT`
   * `SMTP_USERNAME`
   * `SMTP_PASSWORD`
   * `SMTP_FROM`
   * `SMTP_TO`
   * `SMTP_STARTTLS` или аналогичный параметр
   * интервал polling при необходимости.

   Секреты не хардкодить и не коммитить.

8. Формат письма сделать простым:

   * тема: `SMS from <number>`
   * тело: номер отправителя, время получения и текст SMS.
     Корректно поддерживать Unicode/UTF-8.

9. Сервис должен корректно переживать:

   * перезапуск контейнера;
   * временную недоступность SMTP;
   * блокировку SQLite на короткое время;
   * отсутствие новых SMS;
   * несколько SMS, появившихся одновременно.

10. Добавить:

* `Dockerfile`;
* минимальный README;
* `.env.example`;
* healthcheck, если это разумно;
* нормальные структурированные логи без вывода SMTP-пароля.

11. Интегрировать контейнер в существующую Docker-схему аккуратно:

* не публиковать наружу никаких портов;
* не менять существующую адресацию сервисов без необходимости;
* сохранить пользовательский mount `/run/pcscd`;
* после изменений обязательно проверить:
  `docker compose config --quiet`
  и вариант Compose с `docker-compose.cellular-internet.yml`.

Перед реализацией сначала исследовать текущий Compose, volumes и фактическую SQLite-схему. Затем реализовать минимально инвазивное решение и проверить его локально.
